# Warning W101: Pass-through column shadowed by composition body column

## What it means

An upstream row carries a column that passes through a composition's input
port without the port declaring it, and the composition body writes a column
with the same name to one of its output ports. The body column wins (shadows
the pass-through), and this warning is emitted so the author is aware of the
collision.

## Example

```yaml
# compositions/tagged.comp.yaml — the caller's rows carry `id, name, tag`
_compose:
  name: tagged
  inputs:
    inp:
      schema:
        - { name: id, type: string }
  outputs:
    out: t
  config_schema: {}

nodes:
  - type: transform
    name: t
    input: inp
    config:
      cxl: |
        emit tag = 'new'    # replaces the caller's `tag` -> W101
```

## How to fix

The warning points at the composition line that writes the column. If the
composition should replace the caller's value, declare the column on the input
port, as the help prints, so the replacement is part of the port's contract
and the warning stops:

```yaml
_compose:
  inputs:
    inp:
      schema:
        - { name: tag, type: string }
```

If the caller's value should pass through instead, write the composition's
column under another name.

## Technical context

Port schemas are minimum-required and body-wins: upstream rows
may carry additional columns beyond the declared port schema. These
extras pass through the composition boundary. When the body creates a
column with the same name as a pass-through column, the body column wins.
This warning (W101) is informational — it confirms the shadowing rather
than blocking compilation, since the body-wins rule is by design.

It fires once per output port and column, naming the input port whose
caller column is replaced. A column one input port declares and passes on
unchanged does not fire it, even when another input port passes a column of
the same name through undeclared. Today a warning is printed only when the
compile also fails; a successful run does not print it.
