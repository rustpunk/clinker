# Error E129: Ambiguous provenance shorthand

## What it means

A two-part `node.param` shorthand matched the same authored local node name in
more than one composition-call scope. Clinker refuses to choose one because
that would make the result depend on traversal or insertion order.

## Example

```console
clinker explain pipeline.yaml --field 'shared.threshold'
# [E129] provenance shorthand "shared.threshold" matches multiple scoped nodes
#   help: replace it with one exact address:
#     --field '/v1/config/calls/left/nodes/shared/fields/threshold'
#     --field '/v1/config/calls/right/nodes/shared/fields/threshold'
```

## How to fix

Copy the intended exact address from the deterministic candidate list:

```console
clinker explain pipeline.yaml \
  --field '/v1/config/calls/left/nodes/shared/fields/threshold'
```

## Technical context

Each provenance entry is keyed by `PlanNodeId` and typed field. The structured
address retains the enclosing composition-call path and authored local name.
Shorthand remains convenient for the unique case, but exact resolution is
required when repeated local names would otherwise collide.
