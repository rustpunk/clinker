# Warning W367: a fixed-width output cut values to fit their columns

## What it means

A fixed-width output wrote at least one value longer than its column, and that
column is declared (or defaults to) `truncation: warn`. The writer kept the
first `width` bytes of each such value and continued, so the file is complete
and readable, but those cells hold less than the data did.

String columns default to `truncation: warn`; numeric columns default to
`truncation: error`, which rejects the record instead. `truncation: silent`
truncates the same way and reports nothing.

The warning prints to standard error when the run finishes, one line per
affected output, and **does not change the exit code**. For every column that
truncated it gives:

- the exact number of values cut;
- the longest original value, in bytes;
- the column width, in bytes;
- the numbers of the first eight output records that were cut, counting from 1
  across everything the output wrote — every document, and every file of a split
  output. An output that writes one file per source file numbers its files one
  after another in file-path order; a file whose writer fails is numbered when
  it fails. `…` means more records were cut than are listed.

A repeating-group child is named `group.child`. The warning never includes the
values themselves.

## Example

<!-- explain-test: expect-clean -->
```yaml
# Compiles clean, then warns at the end of the run if any name is longer
# than 5 bytes: `name` is a string column, so it defaults to `truncation: warn`.
nodes:
  - type: source
    name: people
    config:
      name: people
      type: csv
      path: ./people.csv
      schema:
        - { name: name, type: string }
  - type: sink
    name: out
    input: people
    config:
      name: out
      type: fixed_width
      path: ./out.dat
      schema:
        - { name: name, type: string, start: 0, width: 5 }
```

Given `people.csv` with the names `Ann`, `Bartholomew` and `Cleo`, the run
writes:

```text
Ann
Barth
Cleo
```

and reports, on a single line:

```text
W367 output 'out': 1 value(s) truncated to fit under `truncation: warn`: name ×1 (longest 11 bytes, width 5; records 2). Widen the column, shorten the value upstream, or set `truncation: error` to reject such records.
```

## How to fix

Pick whichever applies:

1. **Widen the column.** If the file's consumer accepts a wider field, raise the
   column's `width` to at least the reported longest length.

2. **Shorten the value upstream**, in a Transform before the output, when the
   cut is acceptable but you want to choose how the value is shortened rather
   than keep its first bytes.

3. **Reject instead of truncating.** `truncation: error` on the column makes an
   over-long value fail its record, which your error handling then routes, so no
   cut value reaches the file.

4. **Keep the truncation and silence the report** with `truncation: silent` when
   cut values are expected and harmless.

## Technical context

The writer keeps this account in storage sized by the output's schema when the
output opens: a count and a longest length per `warn` column, and eight record
numbers. Recording a truncation therefore neither allocates nor asks the memory
budget for anything, so a `warn` column can never make a record fail, however
many values are cut. A record that is rejected, or never delivered, is not
counted.
