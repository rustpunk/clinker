# Error E372: attempt cleanup incomplete or budget exhausted

## What it means

Clinker began or evaluated bounded attempt cleanup but could not finish within
the current operation. The result remains truthful about selected, removed,
kept, and partially processed attempts. Any visible final belongs to its own
artifact outcome; other artifacts may remain unpublished or have uncertain
durability.

E372 covers these registered failure codes:

- `attempt.retention.budget_exhausted`
- `attempt.retention.cleanup_failed`

Both have `retry_advice: retry_with_backoff`. A later bounded retry may make
progress after transient resource pressure or storage availability changes.

## Example

```text
[E372] attempt cleanup incomplete
operation: purge
execution_id: 018f47a2-9a41-7a27-b4d6-4f7137e3c159
artifact_id: none
final_visibility: some
durability_uncertain: true
failure_code: attempt.retention.budget_exhausted
retry_advice: retry_with_backoff
recovery: clinker attempts inspect pipelines/orders.yaml --execution-id 018f47a2-9a41-7a27-b4d6-4f7137e3c159
```

The workspace-relative inspection command reports the last durable attempt
state before another cleanup request is considered.

## How to fix

1. Run the exact `recovery` command and review the logical attempt and artifact
   states.
2. Preserve any continuation reported by the cleanup operation. A retry must
   remain bound to the same compiled pipeline, owned root, selector, and
   cursor.
3. Wait for the transient condition to clear, then retry with bounded backoff.
4. If the next inspection reports E371, stop automatic retries and resolve the
   ownership, manifest, liveness, or clock policy first.
5. Do not treat partial cleanup as proof that publication completed or that
   every selected attempt was removed.

## Technical context

Enumeration, inspection, and purge are bounded by entry count, considered
bytes, and monotonic elapsed time. Cleanup removes owned artifact data before
durable ownership metadata and revalidates the directory between steps. A
budget stop, interruption, or contained storage failure therefore returns
cleanup debt instead of widening authority or guessing that the remaining
state is safe. The diagnostic stays path-free and carries retry policy from the
shared failure registry.
