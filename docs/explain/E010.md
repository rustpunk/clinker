# Error E010: a node name contains `.`, which is reserved

## What it means

A node declared a `name:` containing a dot. The dot addresses something other
than a node, so a node cannot wear one:

- `split.high` is the `high` branch of route node `split`.
- `enrich.ref` is the node `ref` declared inside the body of composition call
  site `enrich`.

```
E010: node name "enrich.ref" is invalid: '.' is reserved for branch references
and composition call-site paths; rename the node to "enrich_ref" (use
underscores or hyphens) and update every reference to it
```

The rule covers every node kind — `source`, `transform`, `aggregate`, `route`,
`merge`, `combine`, `reshape`, `cull`, `envelope`, `output`, and `composition`
call sites — and it covers nodes declared inside a `.comp.yaml` body.

## Example

Given this pipeline fragment:

<!-- explain-test: expect-code=E010 -->
```yaml
nodes:
  - type: source
    name: raw.orders
    config:
      name: raw.orders
      type: csv
      path: orders.csv
      schema:
        - { name: id, type: string }
  - type: output
    name: write_orders
    input: raw.orders
    config:
      name: write_orders
      type: csv
      path: clean.csv
```

the source fails because `raw.orders` reads as the node `orders` inside a
composition call site named `raw`. Renaming it to `raw_orders` — and updating
the `input:` that references it — compiles.

## How to fix

1. **Rename the node.** Replace each `.` with `_` or `-`: `raw.orders` becomes
   `raw_orders`. The diagnostic prints the corrected name.

2. **Update every reference.** A rename changes the name that downstream
   `input:` / `inputs:` fields, composition port bindings, and
   `[[observability.lineage.dataset]]` bindings must use.

3. **Keep dotted references.** Only the declared `name:` is restricted.
   Consuming a route branch as `input: split.high`, and binding a body node as
   `node = "enrich.ref"`, are the reserved uses and stay unchanged.

## Technical context

Names are joined into derived keys — most visibly the lineage dataset key,
where a composition call site contributes its own name ahead of the node inside
its body. If a name could itself carry the separator, a top-level output named
`enrich.ref` and the body node `ref` under call site `enrich` would render to
one string, one binding would answer for both, and a run would publish a single
dataset as both an input and an output carrying the other's column edges.

The key format escapes a `.` inside a component, so the collision is not
representable; refusing the name here makes it unreachable, and leaves the
escape a safety net rather than the only thing preventing a silently merged
dataset.

The check runs in the plan-time topology pre-pass over every declared node, and
again over composition body nodes at bind time, since the top-level pass never
reads body files.
