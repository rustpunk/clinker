# Error E370: document and correlation rejection cannot be combined

## What it means

The pipeline enables `dlq_granularity: document` on a source and also declares
a `correlation_key`. Both features defer successful output until an atomic
population is known to be clean, but their populations are different: a
document is one source file, while a correlation group is keyed by authored
field values and can cross file boundaries. Clinker has no combined output
writer boundary for those two dispositions, so it rejects the pipeline before
execution.

## Example

```yaml
# Rejected: the same run requests two incompatible atomic populations.
nodes:
  - type: source
    name: claims
    config:
      name: claims
      type: csv
      path: claims.csv
      correlation_key: account_id
      dlq_granularity: document
      schema:
        - { name: account_id, type: string }
```

The diagnostic names both involved sources when the declarations are on
different source nodes:

```text
[E370] source 'claims' declares `dlq_granularity: document`, but source
'claims' declares `correlation_key` ...
```

## How to fix

- Remove every `correlation_key` to retain whole-document rejection.
- Or set `dlq_granularity: record` to retain correlation-group rejection.

Do not duplicate either declaration under another spelling; each rejection
model has one author-facing configuration.

## Technical context

Planning compiles exactly one physical writer mode for each Output. Document
DLQ commits clean source-file populations at document boundaries. Correlation
rejection instead commits clean correlation groups after group disposition.
Selecting either mode by precedence would make the other guarantee false, so
the config validator fails closed before the writer contract is compiled.
