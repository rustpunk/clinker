# Error E366: a `vars.source` block names a source the pipeline does not declare

## What it means

A channel (or group) overlay declares per-source variables under a source name
that the target pipeline has no Source node for. The block would apply to
nothing, so it is rejected rather than silently ignored.

```
channel "globex": source "order" not declared in pipeline (known: orders,
customers, returns)
```

The message lists every source the pipeline does declare, so a typo is usually
visible in the diagnostic itself.

`vars.source` is keyed by the **node name** of the Source — the `name:` on the
node header, which is what the rest of the pipeline wires its `input:` to. That
can differ from the `name:` nested inside the node's `config:` block; the
overlay uses the node name, as every other channel surface does.

## Example

```yaml
# pipeline/base.yaml — the pipeline declares one source, named `orders`.
nodes:
  - type: source
    name: orders
    config:
      name: orders
      type: csv
      path: ./orders.csv
      schema:
        - { name: order_id, type: int }
```

```yaml
# channel/globex/base.channel.yaml — rejected: no source named `order`.
channel:
  target: ../../pipeline/base.yaml
vars:
  source:
    order:
      region:
        type: string
        default: "emea"
```

```yaml
# channel/globex/base.channel.yaml — accepted: the node name matches.
channel:
  target: ../../pipeline/base.yaml
vars:
  source:
    orders:
      region:
        type: string
        default: "emea"
```

## How to fix

1. **Check the name against the pipeline's Source nodes.** The diagnostic lists
   them; copy the one you meant.

2. **Use the node's `name:`, not its `config.name:`.** When the two differ, the
   overlay keys on the node header's name.

3. **If the overlay targets the wrong pipeline, fix `channel.target`.** A
   `vars.source` block that names sources from a different pipeline usually
   means the target path points somewhere unintended.

4. **If the source was removed from the pipeline, remove the block.** It has
   had no effect since the source went away.

## Technical context

Overlay resolution runs before compile, against the parsed pipeline, so it can
see the declared source set and check the key against it. Accepting an unknown
key would make an overlay that silently does nothing indistinguishable from one
that works — the failure mode a channel system can least afford, because the
overlay's whole purpose is to change behaviour per tenant and a no-op looks
exactly like the base pipeline running correctly.

This condition previously shared code E111 with the check for a composition
body that contains no nodes. One code cannot answer two questions:
`clinker explain --code E111` described an empty composition body, which is
unrelated to a channel var scope and names machinery a pipeline using channels
may not have at all. The conditions now have separate codes.
