# Error E368: declared source-type errors exceeded the configured threshold

## What it means

Records failed conversion to types declared in a source schema, and the
cumulative fraction of those failures exceeded
`error_handling.type_error_threshold`. The diagnostic reports both the observed
and configured rates, together with the rejected and total source-record
counts.

The threshold is a fraction from `0.0` through `1.0`. It limits how much bad
source data a `continue` run may tolerate; it does not weaken declared-type
enforcement or turn rejected values into strings.

## How to fix

- Correct the source data when values do not match the declared schema.
- Correct the schema when it declares the wrong type for valid input.
- If the observed error rate is an accepted operational tolerance, raise
  `type_error_threshold` deliberately and keep it within `0.0..=1.0`.
- Inspect the DLQ entries to identify the offending field, value, and source
  row before changing the threshold.

## Technical context

Declared source types are enforced before records enter the executable graph.
Under `strategy: continue`, individual type failures are rejected and counted;
the threshold provides a pipeline-wide stop condition over that population.
Under fail-fast execution, the first type failure already stops the run, so the
rate threshold does not postpone it.
