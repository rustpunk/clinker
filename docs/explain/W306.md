# Warning W306: Combine planner cannot determine optimal driving input

## What it means

A Combine with three or more inputs and no `drive:` field gets this
warning. The driving input is the one whose records go through one at a
time; the other inputs are looked up for each of them. Without `drive:`,
the first input in the `input:` map drives.

The planner is meant to choose the driver from the inputs' row counts,
but those counts are not available yet when the driver is chosen. So
today the warning fires for every Combine of three or more inputs
without `drive:`, and the first declared input always drives
([#1148](https://github.com/rustpunk/clinker/issues/1148)). A two-input
Combine never gets W306; it also drives from its first input.

## Example

```yaml
# Warning W306: three inputs and no drive:
nodes:
  - type: source
    name: orders
    config: { type: csv, path: orders.csv, schema: [...] }
  - type: source
    name: products
    config: { type: csv, path: products.csv, schema: [...] }
  - type: source
    name: categories
    config: { type: csv, path: categories.csv, schema: [...] }

  - type: combine
    name: enrich
    input:
      orders: orders
      products: products
      categories: categories
    config:
      where: "orders.product_id == products.id and products.category_id == categories.id"
      cxl: |
        emit order_id = orders.id
        emit product_name = products.name
        emit category = categories.name
```

## How to fix

Add `drive:` naming the input whose records should go through one at a
time:

```yaml
    config:
      drive: orders
      where: "orders.product_id == products.id and products.category_id == categories.id"
```

Name the input whose records you want one output row (or one
`on_miss:` decision) for, usually the main stream rather than a lookup
table. If the first declared input is already the one you want, you can
leave the warning: the choice is deterministic, so runs are
reproducible.

## Technical context

The driver is not only a performance choice. `match:` picks among the
other inputs' records for each driver record, and `on_miss:` decides what
happens to a driver record with no match, so a different driver gives a
different result. Naming it with `drive:` keeps the output from
depending on how the planner chooses. Whether W306 should stay, and
whether row counts should ever choose the driver, is an open decision
([#1148](https://github.com/rustpunk/clinker/issues/1148)).

W306 is distinct from W305 (no equality conjuncts) because the two
remediations are different: W305 asks for a predicate change; W306 asks
for a `drive:` field. Splitting them lets each warning carry one clear
action.
