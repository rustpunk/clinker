# Error E377: an ordinary composition call uses a rejected inert field

## What it means

`alias:` and `outputs:` are not fields on an ordinary `type: composition`
call. Older parsing accepted them without changing planning or execution, so
they are now rejected at the authored value instead of remaining misleading
state.

## Example

This call is rejected:

```yaml
- type: composition
  name: enrich_orders
  input: orders
  use: compositions/enrich.comp.yaml
  alias: enrich
  outputs: { result: ignored }
```

## How to fix

Use the composition node's `name:` as its namespace. Declare public output
ports in the composition file and reference them downstream:

```yaml
# compositions/enrich.comp.yaml
_compose:
  outputs:
    result: final_stage
```

```yaml
- type: composition
  name: enrich_orders
  input: orders
  use: compositions/enrich.comp.yaml

- type: sink
  name: publish
  input: enrich_orders.result
  config: { name: publish, type: csv, path: out.csv }
```

`alias:` remains valid only inside an overlay `add` operation, where it names
the node being inserted.

## Technical context

The strict composition payload consumes either rejected key only long enough
to emit E377 with its source line. Neither field is represented by
`PipelineNode::Composition` or passed through schema binding. `_compose.outputs`
continues to define the public port contract.
