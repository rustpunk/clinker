# Error E371: unsafe or invalid retained attempt refused

## What it means

Clinker refused an attempt operation because it could not prove that the
retained state was safe to inspect or remove. The diagnostic reports only
logical identifiers and exact outcome fields: the operation, execution ID,
optional artifact ID, final visibility, durability uncertainty, registered
failure code, retry advice, and a workspace-relative recovery command.

E371 covers these registered failure codes:

- `attempt.retention.ownership_refused`
- `attempt.retention.manifest_invalid`
- `attempt.retention.live`
- `attempt.retention.clock_ambiguous`

All four have `retry_advice: policy_required`. Repeating the same destructive
operation is not safe until an operator resolves the reported condition.

## Example

```text
[E371] retained attempt operation refused
operation: purge
execution_id: 018f47a2-9a41-7a27-b4d6-4f7137e3c159
artifact_id: artifact-00000001
final_visibility: none
durability_uncertain: false
failure_code: attempt.retention.ownership_refused
retry_advice: policy_required
recovery: clinker attempts inspect pipelines/orders.yaml --execution-id 018f47a2-9a41-7a27-b4d6-4f7137e3c159
```

The command uses a pipeline path relative to the workspace. Inspection does
not grant cleanup authority and does not mutate the retained attempt.

## How to fix

1. Run the exact `recovery` command from the diagnostic.
2. If the attempt is live, allow its owner to finish or stop it through the
   ordinary process-management policy before trying again.
3. If ownership or the manifest is invalid, preserve the attempt and repair
   the operator-controlled metadata or policy. Do not infer ownership from a
   directory name.
4. If the clock is ambiguous, wait for trustworthy retention evidence or use
   an explicitly reviewed policy decision. There is no safety override.
5. Retry only after the condition has changed and current pipeline validation
   still admits the same logical attempt root.

## Technical context

Retained-attempt cleanup is fail closed. A liveness lock, invalid or unreadable
manifest, unproven ownership, unsupported entry kind, or ambiguous retention
time prevents deletion. Cleanup accepts a compiled pipeline and typed logical
selector; it never accepts a raw deletion path. E371 therefore keeps
`final_visibility` and `durability_uncertain` explicit without disclosing
physical storage locations, credentials, record values, or arbitrary debug
payloads.
