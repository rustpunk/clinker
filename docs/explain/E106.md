# Error E106: Name collision after composition expansion

## What it means

After composition binding, two nodes would have the same fully-qualified
name. A composition call's `name:` supplies its caller-visible namespace, so
sibling calls must have distinct node names.

## Example

```yaml
- type: composition
  name: enrich_a
  input: src
  use: ./customer_enrich.comp.yaml

- type: composition
  name: enrich_b
  input: src
  use: ./customer_enrich.comp.yaml
```

If both calls were named `enrich`, their scoped body nodes would collide.

## How to fix

Give each composition call a distinct `name:`:

```yaml
- type: composition
  name: customer_enrich_a
  input: src
  use: ./customer_enrich.comp.yaml

- type: composition
  name: customer_enrich_b
  input: src
  use: ./customer_enrich.comp.yaml
```

Do not add an ordinary call-site `alias:`. That field has no namespacing
semantics and is rejected with E377. `alias:` remains a separate spelling only
inside an overlay `add` operation, where it supplies the inserted node name.

## Technical context

Composition bodies remain sealed and their scoped planning identities derive
from the call path and composition node name. Ordinary `PipelineNode::Composition`
state contains no alias or call-site output map: `_compose.outputs` defines the
port contract and downstream wiring uses `node.port`.
