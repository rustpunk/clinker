# Error E367: invalid output split naming pattern

## What it means

An Output node's `split.naming` pattern is malformed or does not contain
exactly one sequence token. Clinker cannot publish split files safely unless
each file receives a deterministic, unique name.

The supported sequence form is `{seq:N}`, where `N` is a positive decimal
width such as `{seq:04}`. A pattern with no sequence, more than one sequence,
an invalid width, or an unknown placeholder is rejected during planning.

## Example

```yaml
nodes:
  - type: sink
    name: chunks
    input: rows
    config:
      name: chunks
      type: csv
      path: output/
      split:
        max_rows: 1000
        naming: "part.csv" # rejected: no sequence token
```

The diagnostic suggests a valid pattern such as:

```yaml
naming: "{stem}_{seq:04}.{ext}"
```

## How to fix

Use exactly one valid sequence token and only supported placeholders. Keep the
sequence width large enough for the expected number of files.

```yaml
split:
  max_rows: 1000
  naming: "orders_{seq:05}.csv"
```

## Technical context

Split naming is compiled before execution. Requiring one sequence token keeps
every destination unique without depending on directory enumeration order or
overwriting an earlier chunk. The parsed pattern is then reused by the output
publisher for every split boundary.
