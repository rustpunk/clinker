# Error E110: an extraction selection names a node absent from the execution-plan DAG

## What it means

An extraction request selected a node name that does not exist in the compiled
execution-plan DAG. Extraction can only form a composition boundary around
nodes the plan actually contains, so Clinker rejects the complete selection
before writing a composition file.

```
E110: selected node 'clean_oder' not found in the execution plan DAG
```

Node names are exact and case-sensitive. A spelling from inside a composition
body is also not a top-level DAG node: compositions are selected at their
top-level boundary rather than by reaching into their internal body.

## Example

Given this pipeline fragment:

```yaml
nodes:
  - type: source
    name: orders
    config:
      name: orders
      type: csv
      path: orders.csv
      schema:
        - { name: id, type: string }
  - type: transform
    name: clean_order
    input: orders
    config:
      cxl: "emit id = id"
  - type: output
    name: write_order
    input: clean_order
    config:
      name: write_order
      type: csv
      path: clean.csv
```

an extraction selection containing `clean_oder` fails because the declared
node is named `clean_order`. Selecting `clean_order` uses a name present in the
compiled DAG and allows boundary analysis to continue.

## How to fix

1. **Correct the selected name.** Compare it with the node's exact `name:` in
   the pipeline; in the example, replace `clean_oder` with `clean_order`.

2. **Inspect the compiled plan.** Run `clinker run pipeline.yaml --explain` and
   choose a node name shown in that top-level DAG.

3. **Select a composition as a unit.** If the intended node belongs to a
   composition body, select the top-level composition node instead of an
   internal body node.

## Technical context

Extraction boundary analysis first builds a name-to-node index from the
compiled DAG's topological order. It checks every selected name against that
index before calculating crossing input and output edges. If any name is
absent, analysis returns E110 and no extracted composition is written.

E110 is reserved for this extraction-boundary condition. A channel variable
that shadows a reserved `$pipeline.*` or `$source.*` field uses E117 instead.
