# Error E128: Unknown provenance field

## What it means

A non-empty exact address or shorthand matched no provenance entry in the
compiled plan. Candidate output is deliberately restricted to exact addresses
for the same field name, so an error does not expose unrelated nodes or fields.

## Example

```console
clinker explain pipeline.yaml --field 'missing.threshold'
# [E128] no provenance entry matches "missing.threshold"
#   help: use one exact same-field address:
#     --field '/v1/config/nodes/risk/fields/threshold'
```

## How to fix

Copy one exact address from the diagnostic and replace the failed selector:

```console
clinker explain pipeline.yaml --field '/v1/config/nodes/risk/fields/threshold'
```

If no candidate is listed, remove the invalid `--field` argument or use the
authored composition parameter or schema attribute name.

## Technical context

Internal provenance is keyed by stable plan-node identity plus a typed field,
not by an authored name. Exact versioned addresses resolve that identity
without guessing. RFC 6901 segment escaping preserves Unicode, `/`, and `~`
without normalization or collisions.
