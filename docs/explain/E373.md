# Error E373: a log directive's condition must be one predicate

## What it means

A transform log directive's `condition` is a gate: one expression, evaluated
against each incoming record, that decides whether the directive emits. The
value supplied parsed as more than one statement, so it is not a gate — it is
a small program, and the rest of it would run somewhere the author never
intended.

Clinker rejects the pipeline before execution rather than discovering it at
the first record.

## Example

```yaml
# Rejected: the condition spans two statements.
- type: transform
  name: enrich
  input: orders
  config:
    cxl: "emit amount = amount"
    log:
      - name: transform.large_order
        level: info
        when: per_record
        every: 1
        condition: "amount > 1000
distinct"
        message: "large order"
        fields: [amount]
```

The second line is a separate statement. Note that this is easy to write by
accident: a YAML double-quoted scalar interprets `\n`, so
`condition: "amount > 1000\ndistinct"` produces the same two statements even
though it looks like one line in the file.

## How to fix

Write the gate as a single expression. Combine the terms you want with `and`
/ `or` rather than placing them on separate lines:

```yaml
        condition: "amount > 1000 and region == 'eu'"
```

If what you wanted was a transformation rather than a gate, it belongs in the
transform's own `cxl:` block, not in the directive's `condition`.

## Technical context

The condition is compiled as `filter <condition>` and typechecked against the
transform's **input** row, so the gate sees each record as it arrived rather
than as the transform projects it. Because the authored text is placed into a
program, a value carrying a statement separator compiles into additional
top-level statements. Those statements are not part of any gate, and some of
them — `distinct`, for one — require evaluator state that a gate is never
allocated. Rejecting at plan time keeps that from becoming a runtime failure
partway through a run.

The condition is also capped at 512 bytes and is only valid with
`when: per_record`, because a gate needs a record to test.
