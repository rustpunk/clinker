# Error E104: Call site or channel leaves unbound an input or config the composition needs

## What it means

A composition call site or channel binding does not provide a value for a
required parameter (one without a default) declared in the target
composition's signature, or leaves unbound an optional input port that a
node of the composition reads.

## Example

```yaml
# customer_enrich requires lookup_table (no default)
- type: composition
  name: enrich
  input: src
  use: ./customer_enrich.comp.yaml
  config:
    fuzzy_threshold: 0.9
    # missing: lookup_table
```

## How to fix

Add the missing required parameter to the call site's `config:`,
`inputs:`, or `resources:` map.

The same error reports an input port declared `required: false` that the
call leaves unbound while the composition reads it: a node of the composition
reads it, so that node could receive no row, or an output port carries it, so
the call could write no row. The message names the call, the port and what
reads it, and the help gives the entry to add under the call's `inputs:`:

```text
composition "first": node "u" in `compositions/first.comp.yaml` reads input
port `opt`, which this call does not bind, so the node could receive no row
help: bind input port `opt` at the call, so node "u" receives rows: add under
`inputs:` of composition "first": `opt: dep`
```

The help tries nodes in this order: the nodes feeding the call's other input
ports, then, for a call inside a composition, that composition's own input
ports, then every other node of the calling pipeline or composition in the
order they are declared. A Sink, a Route, a Cull, a node that failed and the
call itself are skipped. Before printing an entry, the compiler binds the call
with it and keeps it only if the call then compiles without this error and
without a new one, so a node whose rows lack a column the port declares, or
carry it with a type the port does not accept, is passed over. The help
prints the entry for the first node that passes. The check covers the call,
not the nodes after it: a node that reads the call and needs a column the
chosen node does not have can still fail once the entry is pasted, and the
next compile reports it. When no node qualifies, the help prints no entry and
says to bind the port to a node whose rows have the columns it declares. Only
a port nothing in the composition reads may be left unbound.

## Technical context

Composition parameters are declared in `config_schema:` with
`required: true|false` and optional `default:` values. A parameter marked
`required: true` with no default must be supplied at every call site and
cannot be deferred to channel overlays. This ensures that a composition
compiles standalone without relying on external configuration.
