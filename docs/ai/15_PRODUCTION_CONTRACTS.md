## How to read this register

Every row separates three facts that must not be collapsed:

- **Observed now** describes the current implementation or repository state.
- **Locked target** records the decision later work must implement.
- **Owner** identifies the phase that must make and verify that change.

The status vocabulary is intentionally small:

- `implemented` — current evidence matches the locked contract.
- `partially-implemented` — part of the boundary exists, but a material gap remains.
- `locked-not-implemented` — Phase 1 selected the target, but current behavior differs.
- `deferred` — the contract explicitly assigns implementation outside the current scope.
- `external-mutable` — the authoritative state is outside the repository and must be refreshed.

Every contract table uses the same ten columns. An Owner names at least one
`Phase N` or versioned `vN` boundary. Evidence names a multiword source or test
surface, a repository validation command, or one or more backticked
repository-relative locators. Each locator names an existing file or directory
and contains no parent traversal; backticks used for code or command typography
do not waive those rules. Last verified is always `YYYY-MM-DD`.

Compatibility describes the migration posture, not Rust visibility. A `pub`
symbol is reachable, but it is a supported integration API only when this
register classifies it that way.

SECU-03 is a Phase 3 STATE decision, not a numbered Phase 1 production
contract. All twelve production-reachable specialized dispatcher boundaries
return `DispatchMismatch` with `runtime.invariant.dispatch_mismatch`,

mutable operator or publication effects. The payload is limited to fixed
dispatcher/kind tags and bounded logical node identity; the finite-attempt
matrix proves cleanup, unchanged intended finals, and retained manifest and
quarantine evidence. Internal algorithm assertions, including locally proven
Output invariants, remain assertions.

### AUTH-08 fixed-width repeating-group slice

Fixed-width sources and sinks now admit one explicit bounded positional group:
`Column.fields` describes an occurrence, `occurs.max` fixes the physical upper
bound, and an optional leading `count_field` controls cardinality without
entering the logical schema. The strict shape participates in patches,
configuration provenance, and semantic identity before the normal planner
admits it. Both format directions share checked layout resolution; the reader
retains one declared-length row and the writer validates a complete
declared-length record before its first destination write. Exact-byte tests
cover zero through maximum cardinality, padding and shifting, adjacent groups,
count disagreement, explicit first/last truncation, stable equal-value order,
malformed layouts, and destination atomicity. See
`crates/clinker-format/src/fixed_width/field.rs`,
`crates/clinker-plan/src/config/multi_value.rs`, and
`crates/clinker-format/tests/fixed_width_repeating_groups.rs`.

This closes only the positional fixed-width part of AUTH-08. Repeated-value
discovery and authoring remain separate work; this evidence must not be read as
completion of that delivery group.
